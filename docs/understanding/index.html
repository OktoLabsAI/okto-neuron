What Okto Neuron is — learning the way you wish you could.

You read a book and forget the sentences but keep the lesson — and you remember which book to return to. Okto Neuron stores the distilled fact and a precise pointer home. Markdown is the truth; the graph is derived and always rebuildable.

The atomic unit02

A Claim is one sentence of truth — and it never floats free.

The smallest unit isn't a node; it's a Claim: a single subject–predicate–object assertion. A Claim reaches in two directions at once. Down by PROV-O edges to exactly where it came from ("which book to return to" made mechanical), and across to the entities it asserts — so a fact and its referents live in one connected graph, not two disjoint halves.

You can always audit a fact: it carries its byte-range anchor home. Don't bypass Block anchoring — it's load-bearing. And the Claim bridges to its subject/object via canonical rdf:subject/rdf:object edges (the source Document also gets schema:mentions to every entity it names) — so reified facts are navigable, not inert. The recent shift03

It stopped being a filing cabinet. It became a companion that curates.

Hand it a document and it extracts knowledge with an LLM, checks it against what it already knows, surfaces correlations and contradictions, and commits on its own — interrupting you only when genuinely unsure.

🗄️ Before — passive store

file → deterministic parse → claims written directly. No judgement, no dedup, no "wait, this contradicts what I knew."

🤖 After — autonomous loop

Ports Pulse's proven KG-consolidation shape (propose → resolve → gate → commit) onto the generic 5-primitive spine. A confidence gate keeps it safe; the markdown vault keeps it reversible.

Two memories, one relay04

Fuzzy recall to land; precise traversal to expand & prove.

Embeddings and graph aren't rivals — they're a relay, and this is the whole intuition behind the read path.

🌫️ Embeddings

Associative, fuzzy. "What feels related to this meaning?" Finds the entry points when you don't know the exact words.

🕸️ Graph

Precise, structured, provenanced. "How does X tie to Y, and where's the source?" Expands and grounds once you've landed.

Vector to find the door, graph to walk the house — the GraphRAG thesis. The unified "one search" that fuses these shipped (2026-05-29) — see the Mechanical tab.
The honest frontier05

The plumbing works. The hard bet is precision at firehose scale.

"Every interaction curated and absorbed" is a firehose. It only stays valuable if write-time curation is both mostly-autonomous and high-precision — else the graph rots into noise. The review queue is the safety valve, but you can't review everything.

The least-built, most-interesting part: abstraction — forming general Concepts from repeated micro-instances (SKOS broader/narrower). That's "how we actually learn," and it's the real frontier. Not the plumbing — the judgement.

The first answer to "you can't review everything" already shipped: a post-ingest curation layer runs after the write path, reconciling entities that were already committed and sweeping the graph continuously in the background. See the Mechanical tab.

Those six boxes are the conceptual shape; the runtime reports five progress stages. The on_progress callback remember() accepts emits exactly these literals, in order: parsing → extracting → embedding → dedup → committing. Only the first three count a block population (done/total are real block counters). dedup and committing have no block denominator, so they tick an item ordinal with an explicitly undeclared total — the server records a blocks population only for the three block-counting stages, because folding an ordinal of 212 into "of 3 blocks" would both clobber the display and trip the ADR 0039 T9 done ≤ total integrity check. remember() also takes on_event and a cooperative should_cancel predicate.
Curation, not extraction, is where the wall clock goes — and it is serial by default. One measured live ingest of a 15,882-byte, 3-block Markdown file took 1,536 s end to end: 271 s of extraction (18%) against 1,266 s of curation (82%), over 177 completion calls and 438,464 input / 28,495 output tokens, committing 25 candidates and queueing 29. Three blocks, twenty-five minutes — against the default local endpoint (127.0.0.1:8123/v1, qwen3.8-27b on a Mac). The same file and model on a separate LAN inference server took 297 s (255 s curation, 163 calls, 407,279 / 26,837 tokens, same units and quality: complete): per-call latency 6.0–9.3 s vs 1.14–2.26 s on an identical payload, so the endpoint alone moves wall clock ~5× while the serial-curation shape stays the same. curation_max_concurrent and curation_batch_size both default to 1 and curation_call_timeout_s is unbounded (the deliberate ADR 0015 opt-ins) — and raising the first may still do nothing, because curation_effective_max_concurrent clamps it back to 1 unless every curation-step model is listed in llm.parallel_capable_models. A vault can be configured for 4-way fan-out and run strictly sequentially with no error. measured 2026-09-18, LAN re-run 2026-09-19 · ADR 0015 · ADR 0039
① Intake & ② Propose07

Anchored Blocks first — then the LLM proposes.

Intake runs the deterministic path: markdown → byte-anchored Blocks (frontmatter, #tags, [[wikilinks]], headings). Propose hands text to LLMExtractor, which calls the configured LLM provider — a LiteLLM-backed layer that routes any backend, local or hosted, through one complete() interface — and parses tolerant JSON into candidates. Each LLM moment (extraction, the merge-judge, ask) is configured independently; extraction runs with reasoning off by default since it only needs to emit structured JSON, and at temperature 0.0 (extract/__init__.py) — determinism is the point when the output is structured JSON. There is no baked-in ask temperature: LLMDefaults.temperature is None, so ask sends whatever the vault resolves, and the 0.7 figure lives only inside the named instruct sampling preset. The curator steps default to 0.2; the judge and resolve calls to 0.0. The endpoint-specific sampler/template params a self-hosted model needs — including the chat_template_kwargs:{enable_thinking:false} switch — are passed through to any self-hosted endpoint (loopback or private LAN / Tailscale), not just loopback; a known hosted API never receives them. (Gating that passthrough to loopback-only silently dropped thinking-off for a LAN inference server, so it reasoned at length and truncated dense blocks before emitting JSON.)

text → LLMProvider.complete()OpenAI-compatible · base_url switch → ExtractionResultNodeCandidate[] + EdgeCandidate[]
A vault with no model configured is refused before the first call. LLMDefaults.model is deliberately the empty string — the built-in defaults never claim a model the configured endpoint may not serve — while provider and api_base do have real values. Dialing that combination used to resolve to openai/ and kill every block with a per-block provider_unavailable ledger row, blaming a provider that was actually up. remember() now raises before the extractor is built when the vault still resolves to the built-in defaults with an empty model, naming llm.defaults.model and the vault path. A vault that pinned its own provider or api_base is left alone — an empty model there is the operator's explicit choice. working tree · not yet published
Only the 5 primitives are valid candidate node types — propositional facts ride a separate claims[] channel, so a subjectless Claim node can never be minted. Sensitive content is pinned local-only — never sent to a hosted provider.
Extraction is escalate-on-truncation by default (auto mode). A 12k Block can produce more JSON than the response token cap allows; the model stops at finish_reason="length" and the tail facts are silently dropped — measured ~15–20% of dense blocks, exactly the dense surfaces behind the 63% extraction-gap. So extract() now defaults to "auto": per block, a "stop" finish accepts the baseline single pass as-is (no extra cost); a "length" finish re-runs that block through the enumerate (Mode B) pipeline to recover the lost facts; any other terminal trips an unexpected-finish guard (kept + logged + counted, never silently escalated). A second-order guard logs CRITICAL if the escalation itself still truncates. Byte-anchoring is identical on both paths. "baseline" and "enumerate" stay selectable per-vault. ADR 0021
Addendum · 2026-07-07 — extraction recall via multi-sample union (samples=k). A single draw at a non-zero temperature is a lossy sample of what a block asserts; a colder draw drops facts a warmer sibling would have caught. So LLMExtractor now takes an optional samples knob (config llm.extraction.samples, default 1 = today's single pass, byte-identical): with samples=k it runs k independent draws per block and unions their candidate sets — deduped on node candidate_id and on the claim/edge (type, src, dst|literal) grain — before the companion's normal dedup / curation. The static system prefix is identical across draws, so a prefix-caching provider reuses it; only the sampling variance differs (at temperature 0 the draws coincide and the union is a deliberate no-op). A bounded truncation-retry re-draws exactly once any draw that hit finish_reason="length" with zero parsed candidates, so a runaway draw does not waste tokens on nothing. Model-free tests pin union deduplication, zero-temperature behavior, and the bounded retry contract. E6 · shipped
Dense facts also live in prose, not just key=value lines and table cells. The extraction prompt now instructs the model to mint a Claim for a scalar, count, or quantity sitting inside a flowing sentence or a capability bullet (e.g. "searches across 24 providers", "uploaded 2,400 files") — binding the Claim to a subject named only in a nearby heading or earlier sentence rather than dropping the fact. Relational prose ("X becomes a one-way mirror of Y") yields an edge and a Claim. This directly attacks the extraction gap behind a subgraph answer: the answer fact gets minted as a byte-anchored Claim instead of staying buried in raw Block text. Prompt regressions pin both prose-embedded scalar and relational cases.
Composite facts bind into one Claim; a Claim's subject is the entity you'd ask about. Two further representation rules. A co-located figure-set — "2,400 files, 80 albums, 0 errors" — mints as one composite Claim (has_measurement, literal capped to noun + qualifiers since the object is hashed into the claim id) instead of being narrated away or atomized into fragments that never reassemble; independent attributes still stay separate (the carve-out). And a fact's Claim subject is bound to the node a reader would name when asking — "AI-generated code", not the sentence's grammatical subject "Verification Gates" — with the original framing preserved as a topology edge. A dense quantity fact also steers to the stable durable entity in scope (ArchiveBox, PhotoShelf, or a person) rather than a document-structure label (a folder, batch, or file name), so the subject is a real entity that commits — and only when no durable entity exists does it keep the structural label. Model-free prompt tests pin composite literals, subject re-pointing, and the independent-attribute carve-out. closed schema: ADR 0020 predicates only, no new primitive
The gate promotes a fact's structural anchor instead of dropping the fact. A literal Claim whose subject was queued (not contradicted) and extracted in the current run can promote that subject as a _salience:low anchor, filtered from recall, ask, and subgraph. Promotion is necessary-not-sufficient: the subject commits only if the relation curator accepts its Claim, so it never creates an orphan. ADR 0031 shipped the same guarded promotion for a topology edge with exactly one dead endpoint; both-endpoints-dead edges still dead-letter, and a queued exact-title duplicate stays with the dedup remap path. The sibling retention fix expanded the curator excerpt from 9,000 characters to CURATION_SOURCE_EXCERPT_LIMIT=16000, covering the full extraction window without changing the per-block prefix shape. ④ Resolve — the "talk-back"08

Two probes ask: have I seen this before?

For each candidate, resolve() runs two checks against the existing graph and produces a confidence score. This is the "resgate dos nós associados" from your sketch — pulling in the related nodes.

🔍
find_similar
Same-type nodes, cosine ≥ 0.82, top-5. Spots near-duplicates.
⚔️
find_contradictions
Claims with same S·P but a different O. Conflict detection.
confidence = 0.7 base  ·  novel +0.2  ·  ambiguous −0.1  ·  contradicted −0.5  → clamped [0, 1]
The probes score; a tiered merge decides identity. Before any candidate commits, resolve runs a layered reconcile against the committed store: Tier-0 exact reconcile_against_store, Tier-1 same-type cosine ≥ 0.82 match, Tier-2 an LLM merge-judge (judge_against_store, confidence ≥ 0.8). ADR 0004 added a fourth pass — judge_within_batch reconciles candidate-vs-candidate inside one remember() batch, catching namespace twins (a bare alice and a prefixed agent:alice born together) that every store-only tier would miss because both look novel.

Addendum · 2026-07-10 — remember() stopped lying about failure. A live-use audit found it could report success while quietly extracting nothing (the "has_heading-only" bug: a configured, reachable-looking LLM whose every call errored, leaving only the structural claim vault.add() mints without any LLM). remember() now resolves to exactly one of three honest outcomes: (a) LLM disabled (llm.enabled=false) — structural-only ingest, RememberResult.llm_disabled=True, never conflated with a failure; (b) total provider failure — every attempted block's extraction call errored, so the ledger run is marked failed and Companion.remember() raises LLMUnavailableError with the real provider error embedded, instead of returning a quiet "done"; (c) partial failure — at least one block succeeded, so it returns normally with the new provider_failures / empty_after_retry_blocks counters populated for caller-side visibility. Batch callers degrade gracefully on the raise: kg rebuild records the file in a failed_files list and keeps going; the folder-watch runner re-queues the file to incoming/ for retry instead of routing it to failed/.
Autonomy on top10

The runner calls remember() while you work.

src/okto_neuron/runner/ polls .marginalia/incoming/*.md, calls remember() on each new file, then moves it to processed/ or failed/ — or, since 2026-07-10, back to incoming/ for retry when remember() raises LLMUnavailableError (a genuinely unreachable/misconfigured LLM, not a bad file). Idempotent, oldest-first, poll-based (no fs-watcher dependency). Runs inside okto-neuron serve or standalone as kg watch.

This is the "companion working in the background." The confidence gate is what makes leaving it unattended safe.
Beyond the inbox — watch any folder (ADR 0025 + 0034). A single global, multi-vault poll loop (server/_folder_watch.py) starts at daemon boot and stat-walks every registered folder_watch.roots directory. Change detection is graph-free — it hashes a file only when (mtime, size) shifts and diffs against a per-vault manifest sidecar, so it never opens a vault handle and scales past the max_open=8 pool. A changed file is enqueued only after it stays quiet for quiet_debounce_s (settle-detection) and no more than once per min_interval_s. Every configured vault owns an immutable runtime and drain worker, so its roots continue ingesting even when no browser tab currently selects that vault; work remains serialized only by that vault's writer lock. Maintenance or deletion may surface a paused_reason for that one runtime, and non-text files it skips surface as skipped_non_text. On re-ingest, a Block whose content_hash matches a prior block that already produced claims is skipped (_incremental.plan_extraction); a Block that did change is narrowed by difflib to just its inserted/replaced hunks (subchunk_units_for_block) rather than re-extracting the whole 12k window. Addendum · 2026-09-03 — Block ids are vault-relative, and stale deterministic claims are retired on every ingest. A 2026-09-03 deep review found _safe_block_path() hashed only path.name (the bare filename), so two same-basename files in different vault directories whose block bytes hashed identically minted the same Block id — the second file's ingest silently reassigned the first file's stored byte range to its own path. parse_markdown() now takes vault_root and hashes the vault-relative path for both the Block id and Block.path (finding 3.4). The same review reconfirmed the accepted gap ADR 0023 itself documents — "no removal of stale blocks" — for the deterministic has_tag/has_heading/links_to Claims a plain re-ingest used to leave doubled and searchable forever (finding 3.5). ingest/__init__.py's _retire_stale_deterministic_claims() now runs unconditionally on every ingest_document() call and supersedes (not detaches — a removed tag is now definitively false, unlike an LLM claim whose source line merely went missing) any such Claim absent from the current parse. See ADR 0023's amendment for the LLM-claim contrast. finding 3.4 · finding 3.5
The reconcile pass — what an edit does to facts that already exist. Extracted into _reconcile_removals and now run on both the normal commit path and the zero-candidate early return (so a pure deletion — an edit whose remnants extract nothing — finally detaches its facts; that path used to return before reconciling). Three moves: supersede a corrected fact (new object for the same subject·predicate); detach a fact whose source text is gone; resurrect a fact whose text comes back. Detach is sentence-unit and attribution aware — each orphaned Block gets an OrphanDiff line-diffing its stored content against the union of current Blocks, and a claim detaches only when one of its anchored lines actually disappeared, so a fact whose line merely moved to a re-sliced Block survives re-chunking churn. Resurrection strips the _superseded/_detached lifecycle facets when a claim's content returns (a mint-path merge leg plus a deterministic resurrect_reverted_claims sweep — load-bearing because the block-hash skip prevents re-extraction on a pure revert). ADR 0024 addendum · F6 · F7 · F9
Corrections are recency-aware, so re-ingesting an old backup can't clobber fresher truth. Every LLM-minted Claim now carries asserted_at — the source file's mtime at ingest (the folder watcher's copy2 preserves mtime; fallback is the ingest date). The supersede prefilter drops any existing claim asserted later than the incoming source, corroboration keeps asserted_at = max(old, new), and the resurrection legs are recency-gated — a restored old backup never resurrects facts that were corrected after it. (Accepted residual: claims minted before this change carry no asserted_at, so the merge judge stays the guard for them.) ADR 0022 addendum · F8
Addendum · 2026-07-03 — auto-supersede is bounded to document lineage. The correction prefilter is a cheap subject-token match, so a vault-wide token overlap plus an aggressive judge could let an edit to one document silently supersede a fact sourced only from an unrelated document. supersede_contradicted now auto-applies a judge-confirmed correction only when it stays in-document (the old Claim is anchored on the same source_path being re-ingested) OR the two Claims share a resolved subject id (S_id). A cross-document, token-only match is deferred, never applied — it is returned separately and surfaced through the claims_supersede_deferred ingest telemetry rather than hiding knowledge behind the operator's back. The bound only ever narrows what is auto-applied. ADR 0022 · Task 5
The read path — unified & anchored12

Write path: done. Read path: unified & anchored.

This was the honest gap; it shipped 2026-05-29. recall() no longer searches Claim nodes only — one fused retrieval now ranks eligible content nodes together, while filtering infrastructure and excluding raw Block substrate from untyped recall/ask. Blocks remain explicitly queryable and anchor every returned Claim's source span.

✅ Built today

Unified retrieval (recall()) across eligible content node types, ask (LLM synthesis over hits), and byte-range provenance grounding on explicitly queried Blocks and LLM-extracted Claims.

✅ Shipped 2026-05-29

A unified retrieval (recall()): per-type vector search → 1–2 hop expansion → fuse by RRF (not score-concat) → apply the content gate → return typed, grounded hits. Untyped recall excludes raw Blocks; type=Block remains available for explicit substrate inspection.

Verified — recall("who is the partner on Okto Neuron?") surfaces Jordan Lee Carter as a byte-anchored Claim; LLM-extracted nodes now carry a real byte-range so ask grounds on source text, not titles.
Seed width differs by surface. recall defaults to k=10 — an agent can re-query and widen on its own, so the first pass stays tight. ask is one-shot (no agentic re-query), so it seeds wider at k=20. The same asymmetry is now discoverable on every surface: the MCP ask tool defaults to k=20 on the validated block path (the earlier MCP default was still k=8 and forced the worse subgraph path — both fixed), the MCP explore tool seeds tight at k=12, and a new CLI ask command mirrors the one-shot-wide / agentic-tight split (with the docstrings + query --k help spelling it out). ADR 0018
The answer prompt is terse; k=20 is the validated win. ask's default system prompt (_ASK_SYSTEM) is the terse "You answer grounded in the provided notes. Be concise.". A controlled 5-sample study (15 runs, same daemon, temp 0.7) confirmed the k=8 → k=20 widen is a real win: answer-presence 0.635 → 0.720, +0.085, McNemar p=0.0018, bootstrap 95% CI [+0.035, +0.140] (excludes 0), neg-control abstention even improving 0.883 → 0.917. Single-run answer-presence at temp 0.7 is not a reliable metric — the deterministic floor (recall@k) and this multi-sample study are the trustworthy signals. Addendum · 2026-05-29 — graph quality. Two refinements landed on top of the unified read path. Provenance nodes are plumbing, not content: the system and LLM extraction Agent/Activity nodes (and raw Block substrate) are graph machinery, so they are filtered out of recall, ask, and the KG browser — content surfaces now show asserted knowledge, never the apparatus that produced it. Dedup is authority control: two mentions of one entity in a note collapse to a single node before staging (edges remapped to the survivor), the FRBR/LRM "manifestations of one work" reconciliation step. And recall is question-aware: for interrogative queries the Claim that answers the question is ranked above the bare topic entity it is about — the canonical KGQA move of ranking the incident triple, not the focus entity. The grounding is established IR/library science: KGQA triple-ranking, coordination-level matching for coverage, and FRBR/LRM for dedup.

After the write path — post-ingest curation13

The graph keeps getting tidier after the fact — without rewriting itself.

The write-path gate decides one candidate at a time, in the moment. A separate post-ingest layer works over knowledge that's already committed — catching the duplicates and drift that only become visible once many notes have landed. It runs on the daemon, never on the hot write path. Three distinct mechanisms, deliberately kept apart because the project's edge-id-collision history makes in-place bulk rewrites unsafe.

reconcile · off-graph
Already-committed entities that turn out to be the same thing are merged into an off-graph equivalence class in .marginalia/authority/index.json (skos:exactMatch, not owl:sameAs). The stored graph is never mutated — reads fold the class to its canonical node at query time (query.py · _fold_equivalence). Fully reversible by dropping the entry. ADR 0008
♻️
heal · the only topology rewrite
When the topology genuinely must change, kg rebuild / heal does it the only safe way: copy into a fresh graph (copy_graph_canonicalizing) then atomic-swap. No in-place edge mutation. Bulk in-place migration was retired. ADR 0007
⏱️
scheduler · propose & detect only
A debounced background loop (server/_scheduler.py) sweeps as you ingest: it proposes candidate merges and mints drift Findings. It can never auto-apply a merge — surfacing for review is the whole point. ADR 0009 P4
A per-vault control plane drives it all. Each immutable vault runtime owns its curation queue, writer lock, and leased Ladybug handle, so blocking work in one vault cannot retarget or freeze another vault. Admin endpoints (/api/v1/reconcile/*, /api/v1/authority/*, /api/v1/curation/*) and an SPA dashboard make each job, the scheduler, and every equivalence class visible and executable; Browse and Graph show a variant_count badge on folded nodes. The reconcile layer carries its own review surface — .marginalia/reconcile/queue.json via kg reconcile review-* — distinct from the write-time review queue.

Addendum · 2026-09-03 — okto-neuron add is structural-only by design; remember and folder-watch extract. The CLI's okto-neuron add goes through POST /add, which writes a Document + Block directly with no LLM extraction — the deliberate add-vs-remember split (server/_ingest_queue.py's record_completed docstring). POST /remember (the MCP remember tool's REST twin) and the folder-watch runner both call Companion.remember(), which runs the full six-stage pipeline above. POST /add's target path is directory-aware (_safe_add_target): a well-formed relative path keeps its full subpath under .marginalia/sources/, so notes/a/README.md and notes/b/README.md land at distinct files instead of collapsing onto one and minting the same document id (finding 3.4-e2e); only an absolute, drive-letter, or ..-traversing path falls back to a sources/<sha256(client_path)[:16]>/<name> hashed subdirectory, keyed by the client-posted path string (not file content), so re-adding an edited file at the same path keeps updating the same document. finding 3.4-e2e
Addendum · 2026-09-03 — surface-parity security hardening. Three gaps closed between REST and its siblings. sensitivity is a strict enum on both surfaces: the MCP remember tool was already Literal["local_only", "default"] (server/runtime.py); REST's POST /remember used to silently coerce any other value — including typos like "local-only" — down to "default". It now runs the same values through _parse_sensitivity() and returns 400 on anything else. MAX_QUERY_K now caps every k-accepting route: the legacy bare /query, /recall, and /ask routes never checked k against the cap their /api/v1 siblings already enforced; all five routes now share one _k_cap_error() helper. Resolve-review routes are loopback-gated: POST /resolve-review(/batch) performed real graph writes without the remote_config_allowed loopback check every other write route enforces; GET /review-queue is gated too, since it hands out the candidate ids the write needs. finding 3.12 · finding 3.13 · finding 3.21
